#Module [v2.1-alpha.11+]

Starts a new module or reopens an existing module.

#Module ModuleName

Parameters

ModuleName

Type: String

A unique name for use with Import.

[v2.1-alpha.20+]: The name may be enclosed in a single pair of quote marks, which is recommended if it is not a valid identifier.

Remarks

The new module starts with an empty global namespace and implicit import from the built-in module.

Warning: ModuleName must not coincide with a module file if the file containing the #Module directive was included as a result of importing a module from file. In such cases, which import statements will correspond to the file or to the directive is unspecified.

Excluding the cases described above, modules defined this way take precedence over modules in the file system, but only for the exact ModuleName used in the directive.

The risk of conflict can be reduced by using a ModuleName containing characters which cannot be used in a file path. For example, #Module "?my/module" would be imported by Import "?my/module" as myModule. Including the name of the script or author may further reduce the risk.

[v2.1-alpha.20+]: If ModuleName is AHK, __Main or a name used with a previous #Module directive, the existing module is "reopened", allowing startup code and definitions to be added.

Warning: #Module generally should not be used in any file which will be included multiple times, as the code of the module would be duplicated.

When Import loads a file, the module automatically begins at the start of the file and the #Module directive should typically not be used. However, the directive can be combined with #Include, and can be used to combine modules into one file.

#Module cannot be used within a block or as the body of a control flow statement.
